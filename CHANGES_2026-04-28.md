## 3. Body Map Rewrite

### Problem (reported by Dr. Ashwini)
- Two parallel modes exist: free-marker (dot/rectangle/ellipse) and highlighted-region.
- The highlighted-region mode "is not working as expected."
- When chief complaints contain >1 symptom, only the **first** sentence is rendered on the body chart — symptoms 2 and 3 are stored but not displayed.

### Decision
- [ ] Drop the free-marker variant. Make **highlighted-region** the single, universal body map.
- [ ] Rewrite the body-map component end-to-end (logic + rendering).
- [ ] Fix multi-complaint rendering: every entered symptom must map to the chart, not just the first.
- [ ] Verify storage layer is correct (data is stored — issue is rendering only).

## 9. Analytics — Theory of Change-Aligned Metrics

### Source
- Meeting discussion + Theory of Change PDF (shared by Anish, Apr 2026).
- Arnav (M16) WhatsApp note (23/04/26).

### Two levels of reporting
1. **Donor / generic stakeholder dashboard** — high-level counts.
2. **Program-team dashboard** — deeper effectiveness metrics.

### A. Donor / Stakeholder metrics (DMQY-style: Daily / Monthly / Quarterly / Yearly)
- [ ] Total **home-care visits** per period
- [ ] Total **consultations** (physician / nurse / physiotherapist / psycho-social)
- [ ] Total **deaths** per period
- [ ] **Kilometers covered** in home-care visits
- [ ] Total **patients seen** per period

### B. Program-effectiveness metrics
- [ ] **Death chart over time** — already partially built; fix the spike caused by all historic entries landing on a single import date.
- [ ] **Place-of-death distribution** (pareto): home / hospital / in-transit, varying over time. Source data: Satish is currently entering zone-wise death line-list; will be ingested.
- [ ] **PPS score trajectory** for **non-best-supportive-care** patients (proxy for intervention success in mitigating suffering).
- [ ] **ESAS score trajectory** for non-best-supportive-care patients.
- [ ] **Morphine / opioid usage** — count of patients given morphine; total dispensation over time. Proxy for "access to opioids" — a core palliative-medicine metric.
- [ ] **Best-supportive-care vs non-best-supportive-care** patient counts.
- [ ] **FAITH spiritual-distress score** — currently not captured in app. Future work: add spiritual assessment form, capture FAITH questionnaire score, show distress-level distribution. (Dr. Ashwini confirmed FAITH is the standardized tool.)
- [ ] **Total visits across all patients** (replaces the misleading "average visits before death" metric — being deprecated as it skews reality when one patient has 4 visits and another has 1).
- [ ] **Follow-up widget activity graph** — shows in which week most follow-ups happen.

### C. Connection-to-other-organizations module (Outcome 3 of ToC)
- [ ] Repository of:
  - Govt social-welfare schemes (national + state) for cancer patients / families
  - NGOs working in cancer care (name, contact, services offered)
  - Cancer-survivor specialist orgs
  - Scholarship / education-aid orgs for survivor children
  - Vocational-training orgs
  - Post-death logistics: ambulances, crematoria (+ docs required, contact, distance), religious-org priests by zone (Hindu / Muslim / Christian / Jain / etc.)
- [ ] Anvita / Ashwini / Ramesh (client side) drafting the schema/template.
- [ ] **Web-scrape support from our side**: use browser automation to populate the repo (Google Maps lookup for crematoria, NGO contact details, etc.) once client shares the column schema.

### D. Activity-based metrics (from ToC PDF)

- [ ] Multi-disciplinary team participation per visit.
- [ ] Telemedicine consultation count.
- [ ] Capacity-building sessions conducted.
