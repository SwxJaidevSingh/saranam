## 2. PPS Score → Priority Linking

### 2.1 Mapping (inversely proportional — low PPS = high priority) `[14:20 – 14:38, 19:23 – 19:39]`

| PPS %    | Priority |
| -------- | -------- |
| 0 – 40   | **High** |
| 50 – 70  | Medium   |
| 80 – 100 | Low      |

**Note:** Earlier, the system prioritized **high PPS = high priority**. This is incorrect. **Low PPS → High priority.** Invert the logic.

### 2.2 Auto-update registration form from Assessment PPS `[16:59 – 17:12, 18:46 – 20:09]`

- When PPS score is entered/updated in the **initial assessment** (or subsequent visits), the "Not determined / High / Medium / Low" field on the **registration form** must auto-update according to the table above.
- Do **not** overwrite previous values — keep them longitudinally so the change over visits is preserved.

### 2.3 Longitudinal PPS tracking `[20:10 – 21:29]`

- Store PPS score **per visit** (not just latest).
- Show trend / graphical representation of PPS over time in patient history / past records.

### 2.4 Remove the free-form High/Medium/Low priority input on scheduling `[15:40 – 16:28]`

- Replace with the derived PPS-percentage-based priority (using 2.1 mapping).
- "Not determined" remains a valid state for patients whose PPS hasn't been assessed yet. `[16:37 – 16:45]`

### 5.2 Flexible timing slots (for non-opioid medicines) `[32:08 – 34:09]`

### 5.3 Double/triple dose multiplier — already implemented ✓ `[29:27 – 31:07]`
