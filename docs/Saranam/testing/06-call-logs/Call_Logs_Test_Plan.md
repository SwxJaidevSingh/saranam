# Call Logs (Smart Outreach) — Manual Test Plan

**Module code:** CL  &nbsp;|&nbsp;  **Version:** 1.0  &nbsp;|&nbsp;  **Date:** 2026-06-01
**Product:** Saranam India Health Care — palliative / home health-care platform
**Production URL:** https://saranam.fieldintel.ai  &nbsp;|&nbsp;  **Module route:** `/call-logs`

## Purpose & How To Use

This pack is the GO-LIVE manual test suite for the **Call Logs / Smart Outreach** module. The testing team executes each case in a browser and records the outcome in Excel.

- Work top-to-bottom. For every case, follow the numbered **Steps**, enter the **Test Data**, and compare what you see against the **Expected Result**.
- Keep browser **DevTools → Network and Console** open for all cases; API-level cases require you to inspect the actual request method/path/payload and the HTTP status code.
- Record your observation in **Actual Result**, set **Status** to `Pass` / `Fail` / `Blocked` / `N/A`, and put any defect ID, screenshot reference, or note in **Remarks**.
- Cases marked **(KNOWN DEFECT)** in the title document an existing code-level issue; they are expected to **Fail** until fixed — log the defect ID from the Defects list at the bottom.
- This module is **admin-only**. Run permission cases (CL-001..CL-006) first; the rest require an admin session.
- Test data uses realistic India values (+91 mobile numbers, Indian patient names, palliative call outcomes).

## 1. Scope

**In scope**

- Permission / route guard: admin-only access to `/call-logs`; sidebar item visibility for non-admins.
- **Dial tab:** priority outreach queue (OutreachQueueView), patient search, pagination, status badges, Call / Call-Caregiver dropdown, schedule-for-later popover, manual SOP open.
- **Staff Registry sidebar** (StaffSidebar): on-duty toggle (persisted), available count, busy state, pagination, empty state.
- **Live Call HUD** (CallHUD): live session list, expand/collapse, document (SOP) and end-session actions, 5-second call-status polling.
- **Initiating a call** via Exotel make-call: from/to derivation, no-available-staff guard, missing-number guard, 403 credential error, generic failure.
- **SOP Documentation modal:** severity / relationship / reason / symptoms / advice / notes capture, escalate flag, save, view existing.
- **History tab:** Call Logs sub-tab (Exotel calls list, recording playback, status colours, stat cards, empty/error states), SOP Documentation sub-tab (paginated history), date-range filter, refresh, export.
- **Escalated tab:** persisted escalations, severity colour bar, HomeCare action, Follow-Up scheduling, Dismiss.
- **Scheduler tab:** persistent schedule list, add, remove, auto-generate weekly plan, empty state.
- **EmailModal:** compose subject/body, required-field disabling, send, cancel (component/intended level — see Defect DEF-CL-02).
- **API-level** validation of every endpoint with payloads and 2xx/4xx/5xx handling; 401 → refresh → login flow.
- **Data integrity:** SOP appears in history/against patient; escalation flag surfaces in Escalated; schedule add/remove persists.

**Out of scope**

- Exotel telephony internals, voice connectivity, recording generation, Exotel billing.
- Inbound routing webhook (`/api/exotel/inbound`) server-to-server behaviour.
- Patients / Providers module CRUD (validated only as data dependencies).
- SMTP server provisioning and email deliverability (only the send-email request/response contract).
- Backend unit, load/performance, and penetration testing.
- HomeCare referral routing (client-only stub, no API — see DEF-CL-05).

## 3. Roles & Access (Admin-Only)

- `/call-logs` is wrapped in `ProtectedRoute requiredRole="admin"`.
- `hasRole(role)` returns `user?.role === role`, so **only** a user whose role is exactly `admin` can render the page.
- A non-admin (`data_entry`, `viewer`) sees a full-page **“Access Denied”** message; an unauthenticated user is redirected to `/login`.
- **API auth is inconsistent** (verify in CL-078 / CL-079): `agents`, `agent-status`, `sop`, `sop/history`, `scheduler` (all methods), `scheduler/auto-generate`, `send-email` all use `@jwt_required()`. **But** `exotel/calls`, `make-call`, `call-status/<sid>` and `inbound` have **no** JWT guard.
- **Sidebar visibility defect (DEF-CL-01):** the nav entry `{name:'Call Logs', href:'/call-logs', permission:null}` is filtered by `!item.permission || hasPermission(...)`. Because `permission` is `null` the item is **always shown**, so it is **not** hidden for non-admins — they see it and are blocked only on click.

## 4. API Endpoints

Base URL: `VITE_API_URL` (default `http://localhost:5000/api`). The axios client attaches `Authorization: Bearer <access_token>`; on `401` it posts `/auth/refresh` once and retries, and on refresh failure clears storage and redirects to `/login`.

| Method | Path | Purpose / Codes |
|---|---|---|
| `GET` | `/api/exotel/calls` | List Exotel call logs; query params start_date, end_date. Returns {Calls:[...]}. NO JWT guard. 500 {error} on Exotel failure. |
| `POST` | `/api/exotel/make-call` | Initiate outbound call. Body {from,to,patient_name,provider_name}. 400 if from/to missing; passes through Exotel status (e.g. 403 invalid creds), 500 on request exception. NO JWT guard. |
| `GET` | `/api/exotel/call-status/{call_sid}` | Fetch live status of a call SID. Returns {Call:{Status,...}}. Passes through Exotel error code, else 500. NO JWT guard. |
| `GET` | `/api/exotel/agents` | List active providers joined with persistent on-duty status (is_on_duty mapped to active). JWT required (401 if missing). 200 array. |
| `PUT` | `/api/exotel/agent-status` | Set agent on-duty status. Body {provider_id,is_on_duty}. 400 if either missing; 200 on success. JWT required. |
| `GET` | `/api/exotel/sop` | List escalated SOP records. Returns {escalations:[...]}. JWT required. 200. |
| `POST` | `/api/exotel/sop` | Save SOP documentation for a call. Body is full SOP payload incl. patient_id, severity, escalate, etc. 201 on success. JWT required. |
| `GET` | `/api/exotel/sop/history` | Paginated SOP documentation history. Query start_date,end_date,page,per_page. Returns {items:[...],total}. JWT required. 200. |
| `GET` | `/api/exotel/scheduler` | List persistent scheduled outreach calls. Query start_date,end_date. Returns {schedule:[...]}. JWT required. 200. |
| `POST` | `/api/exotel/scheduler` | Add patient to outreach schedule. Body {patient_id,scheduled_date,notes}. 400 if patient_id or scheduled_date missing; 201 on success. JWT required. |
| `DELETE` | `/api/exotel/scheduler/{schedule_id}` | Remove a schedule record by UUID. 200 on success; 404 if not found; route expects a valid uuid (non-uuid path = 404 routing). JWT required. |
| `POST` | `/api/exotel/scheduler/auto-generate` | Auto-generate next-week outreach plan. No body. 201 on success. JWT required. |
| `POST` | `/api/exotel/send-email` | Send follow-up email to a patient. Body {patient_id,subject,body}. 400 if any missing; 404 if patient/email not found; 400 if no email on file; 500 if SMTP not configured; 200 on success. JWT required. (UI caller is orphaned — see defects.) |
| `GET/POST` | `/api/exotel/inbound` | Exotel dynamic-routing webhook (server-to-server). Out of UI scope; listed for completeness. |

## 5. Test Data & Preconditions

- **Admin user** (`role='admin'`), e.g. `admin@saranam.test`, to access `/call-logs`.
- **Non-admin user** (`role='data_entry'` or `'viewer'`) to verify Access Denied and sidebar behaviour.
- **≥12 patients** so pagination (PER_PAGE = 10) yields 2 pages. Include one with **no** `last_call_date` (→ NEVER CONTACTED), one called **today** (→ CONTACTED TODAY), one called **~3 days ago** (→ SCHEDULED), one called **>7 days ago** (→ OVERDUE - 7D+).
- **Caregiver patient:** one WITH `primary_caregiver_phone` + `primary_caregiver_name` (e.g. *Lakshmi Iyer*, caregiver `+91 98860 12345`) and one WITHOUT (single Call button).
- **Phone coverage:** a patient with a valid +91 mobile (e.g. *Ramesh Kumar*, `+91 99000 11223`) and one with **no phone** on file (missing-number guard).
- **Email coverage:** a patient with a valid email and one with **no email** on file (send-email 400/404 paths).
- **≥2 active HealthcareProviders** so the Staff Registry has togglable agents; at least one can be set On Duty.
- **Exotel env** (`ACCOUNT_SID`, `API_KEY`, `API_TOKEN`, `EXOTEL_CALLER_ID`): a valid set for happy path, plus a way to force a **403** (invalid key/token) for the credential-error toast.
- **Pre-seed ≥1 escalated SOP** (escalate=true, severity 'high') and several non-escalated SOPs spanning the date range.
- **Pre-seed ≥1 scheduler record** (or add during testing) to validate list / remove / date display.
- Tooling (Postman/curl) with and without a valid JWT for the API-level cases.
- Browser DevTools (Network + Console) open throughout; React error overlay enabled (non-prod) to catch the hook-order crash in CL-077.

## 7. Severity Legend & Sign-Off

### Defect severity legend

| Severity | Definition |
|---|---|
| **Critical (S1)** | Go-live blocker. Data loss/corruption, security/permission breach, or a core flow (place call, save SOP, schedule) completely broken with no workaround. |
| **High (S2)** | Major function fails or is significantly wrong; workaround is costly. Affects many users or a key admin workflow. |
| **Medium (S3)** | Function partially fails or behaves incorrectly in a limited scenario; reasonable workaround exists. |
| **Low (S4)** | Minor/cosmetic — UI polish, copy, spacing, non-blocking validation nicety. |
