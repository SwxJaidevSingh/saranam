## Purpose & How to Use

This document is the GO-LIVE manual test pack for the **Analytics** module of the Saranam India Health Care platform (React frontend + FastAPI/Flask backend). It is to be executed **manually** in a browser by the testing team, recording **Pass/Fail** in the *Status* column (and notes in *Actual Result* / *Remarks*).

How to use:
1. Set up the test data / preconditions in **Section 5** before starting.
2. Work through the cases in **Section 6** in ID order (ANL-001 … ANL-057). Each case is self-contained with numbered steps and an explicit expected result.
3. For every case, fill **Actual Result**, set **Status** (Pass / Fail / Blocked / N/A), and add any **Remarks** (defect ID, screenshot ref, deviation).
4. Use DevTools (Network + Console) where a case references an API call, query param, or HTTP status code.
5. Log defects against the **Severity legend** in Section 7 and complete the sign-off.

> **Summary:** Manual GO-LIVE test pack for the Saranam India Health Care Analytics module. Covers the Analytics Dashboard shell at /analytics (permission guard view_analytics), tab/view navigation, the four LIVE views (Patient Analysis, Form Analysis, Vitals Analysis, Donor/ToC Analytics), the shared DateRangePicker (presets + custom calendar), the patient-type filter, Refresh, the ExportButton (PDF + CSV), the donor sub-controls (period selector, demo/real-data toggle, Refresh, browser-print PDF), and every backend endpoint in app/analytics/routes.py reachable from the UI. Includes loading/skeleton states, empty-data states, API 4xx/5xx/timeout error handling, permission/session checks, and cross-module data-integrity checks. The /analytics/forms and /analytics/forms/:formId Advanced Form Analytics sub-pages are covered only with light load/guard cases — deep form-analytics testing is OUT OF SCOPE for this engagement.

## 3. Roles & Access

All three analytics routes (/analytics, /analytics/forms, /analytics/forms/:formId) are wrapped in ProtectedRoute with requiredPermission="view_analytics". A logged-in user WITH the view_analytics permission sees the dashboard; a logged-in user WITHOUT it is shown the in-app 'Access Denied — You don't have permission to access this page.' panel (ProtectedRoute). An unauthenticated user (no user in AuthContext) is redirected to /login. Every analytics API request requires a valid JWT in the Authorization Bearer header; the backend routes are decorated with @require_auth and return 401 when the token is missing/invalid. NOTE: the AnalyticsDashboard, VitalsAnalysisView and DonorAnalyticsView issue their data calls with a RAW axios instance + manually attached localStorage access_token (VITE_API_BASE_URL), NOT the shared apiClient — so the automatic 401 refresh-and-retry interceptor in api/client.js does NOT apply to these calls; an expired token surfaces as an error state rather than a silent token refresh.

## 4. API Endpoints

All endpoints are under the Flask blueprint prefix `/api/analytics` and decorated with `@require_auth`. Only endpoints reachable from the shipped UI are exercised; others are listed for reference.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/analytics/dashboard` | Patient-view metrics. Query: start_date, end_date (sent as full ISO timestamps by the UI), patient_type (new\|active when filter != all), filters (JSON). Returns summary{total_patients,new_patients,active_patients,total_forms,growth_rate}, demographics{age_distribution,gender_distribution}, trends{registration_over_time,...}. 200 ok; 500 {error} on failure. |
| GET | `/api/analytics/deaths/impact` | Palliative outcome KPIs. Query window_days (default 30, must be 1..3650 else 400). Returns deaths_in_window, avg_visits_before_death, deaths_by_month, deceased_patients. Used by Patient view + Vitals view. |
| GET | `/api/analytics/forms` | Form-view analytics. Query start_date, end_date. Returns summary{total_forms,total_submissions,average_completion_rate,average_completion_time_minutes}, status_breakdown, top_forms, submission_trends, completion_funnel. 200 ok; 500 {error}. |
| GET | `/api/analytics/vitals/summary` | Population vitals improvement summary. Returns {success,data:{total_patients_with_vitals,vitals_summary{...}}}. Powers Patients-Tracked KPI + improvement aggregates. |
| GET | `/api/analytics/vitals/distribution` | Distribution of latest vital values across patients, keyed by vital (bp_systolic, bp_diastolic, pr, spo2, temperature, rr, grbs) with buckets, normal_range, unit, total. Powers the Vitals Distribution chart. |
| GET | `/api/analytics/vitals/correlation` | Correlate vitals change vs ESAS/PPS score change. Query score_type=esas\|pps (default esas). Returns correlations{vital:{improved/stable/deteriorated:{avg_score_change}}}, patients_with_both. |
| GET | `/api/analytics/vitals/top-movers` | Most improved/deteriorated patients. Query direction=improved\|deteriorated, limit (default 10). Defined in api/analytics.js but the UI fetch is commented out — endpoint exists, no live caller. |
| GET | `/api/analytics/donor/overview` | Donor StatTiles + previous-period deltas. Query start_date, end_date (YYYY-MM-DD). 400 on bad date; 500 {error}. |
| GET | `/api/analytics/donor/visits-timeline` | Bucketed visit counts split by visit_location (home/opd/ipd/phone). Query start_date,end_date,period (daily\|monthly\|quarterly\|yearly). |
| GET | `/api/analytics/donor/deaths-timeline` | Bucketed raw death counts (no spike suppression). Query start_date,end_date,period. |
| GET | `/api/analytics/donor/consultations-mix` | Team-role encounter counts across visits in the period. Query start_date,end_date. |
| GET | `/api/analytics/donor/distance-timeline` | Estimated KMs/week from approved weekly schedules. Query start_date,end_date. |
| GET | `/api/analytics/donor/opioid-usage` | Opioid/morphine usage: distinct-patient count + dispensation timeline. Query start_date,end_date,period. |
| GET | `/api/analytics/donor/telemedicine-timeline` | Teleconsult session counts (video+voice). Query start_date,end_date,period. |
| GET | `/api/analytics/donor/multidisciplinary` | Avg distinct team-roles per home visit + multi-disciplinary visit %. Query start_date,end_date. |
| GET | `/api/analytics/donor/followups` | Patients receiving follow-up visits + follow-up volume timeline. Query start_date,end_date,period. |
| GET | `/api/analytics/donor/place-of-death-by-zone` | Deceased counts grouped by (zone, place_of_death); also totals_by_place/totals_by_zone/grand_total. Query start_date,end_date. |
| GET | `/api/analytics/donor/loss-to-followup` | Active alive patients with no completed visit in N+ days. Query threshold_days (default 60), limit (default 50). Note: UI calls this WITHOUT period/date params. |
| GET | `/api/analytics/donor/vehicle-utilization` | Per-vehicle weekly slot count + utilization % vs target. Query start_date,end_date,target_slots_per_week (default 25). |
| GET | `/api/analytics/donor/enrollment-to-death` | Distribution of days from enrolment to death; flags late-referral patterns. Query start_date,end_date. |
| GET | `/api/analytics/donor/registration-to-first-visit` | Time from registration to first completed visit in home-care days. Query start_date,end_date,target_homecare_days (default 8, must be 1..365 else 400). |
| GET | `/api/analytics/forms/advanced/:formId/overview` | (OUT OF SCOPE / light) Advanced form overview for /analytics/forms deep-dive. |
| GET | `/api/analytics/forms/advanced/:formId/funnel` | (OUT OF SCOPE / light) Field drop-off funnel for a form. |
| GET | `/api/analytics/forms/advanced/:formId/heatmap` | (OUT OF SCOPE / light) Day-vs-hour usage heatmap for a form. |
| GET | `/api/analytics/forms/advanced/:formId/fields/:fieldId/distribution` | (OUT OF SCOPE / light) Value distribution for a field. Query field_type. |

- Account A — 'analyst@saranam.test': logged-in user WHOSE role/permission set INCLUDES view_analytics (e.g. admin or analytics-enabled role).
- Account B — 'fieldnurse@saranam.test': logged-in user WHOSE role/permission set does NOT include view_analytics (to verify Access Denied).

- At least a handful of deceased patients within the last 30 days (with visits logged before death) so Deaths(30d) and Avg-Visits-Before-Death are non-zero; plus deceased patients with enrolment dates and place_of_death + zone for donor charts.
- Patients with both initial and follow-up vitals (BP, PR, SpO2, temperature, RR, GRBS) and ESAS/PPS scores so vitals summary/distribution/correlation return data.
- Visits across home/opd/ipd/phone locations, some with team_members carrying role labels, plus teleconsult sessions and opioid (narcotic) dispensations so the donor timelines are populated.
- Approved weekly schedules with vehicles assigned (e.g. KA-01-AB-1234) so distance + vehicle-utilization charts render.
- Several published forms with submissions in varied statuses (draft/submitted/verified) within the test window for the Form view.
- Known reference counts noted before testing: exact total patient count from the Patients module list (for data-integrity comparison) and the count of patients registered in a chosen month.
- A test window of interest: 2026-01-01 to 2026-05-31 (custom range) and the default Last-12-months (2025-06-01 to 2026-06-01).
- Browser DevTools available (Network + Console tabs) to verify API calls, query params, status codes, and to simulate offline/throttled/blocked responses.
- Production URL https://saranam.fieldintel.ai reachable; today's date treated as 2026-06-01.

## 7. Severity Legend & Sign-off

### Defect Severity Legend
| Severity | Definition | Example |
|---|---|---|
| **S1 — Critical** | Go-live blocker. Module unusable, data loss/corruption, security/permission breach, or wrong figures presented to stakeholders as real. | Donor view stuck in demo mode shows fabricated numbers as real; analytics readable without `view_analytics`; dashboard crashes/blank on load. |
| **S2 — High** | Major function broken with no easy workaround. | Date-range change does not refetch; a StatCard shows wrong count vs source of truth; export fails for all views. |
| **S3 — Medium** | Function partially broken; workaround exists. | One chart empty while data exists; export missing a section; one donor endpoint failure blanks the whole donor view. |
| **S4 — Low** | Cosmetic / minor. | Wrong branding text ("CV Raman Health") on exports; label/spacing; tooltip wording. |

### Status Values
`Pass` · `Fail` · `Blocked` · `N/A` (not applicable / could not set up).

### Known Code Observations to Confirm During Execution
- **Branding (S4):** PDF/CSV exports are titled/headed **"CV Raman Health"**, not Saranam (`ExportButton.jsx`).
- **Mock data (S1/S2 risk):** Donor / ToC view has a **demo-data toggle**; if left on, fabricated numbers (`donorMockData.js`) are shown — verify it defaults OFF and is clearly labelled (ANL-033).
- **401 handling (S3):** Dashboard / Vitals / Donor use a **raw axios instance** (not `apiClient`), so the automatic 401 refresh-and-retry interceptor does **not** apply to analytics calls (ANL-004, ANL-054).
- **Export coverage (S3):** The top-bar Export only builds Patient/Form data; on Vitals/Donor tabs the export payload is `null` and yields a near-empty report (ANL-050).
- **Donor error coupling (S3):** All 14 donor endpoints are awaited in one `Promise.all`; any single failure blanks the entire donor view (ANL-037).
- **Date param inconsistency (S4):** Patient `/dashboard` sends full ISO timestamps; Donor sends `yyyy-MM-dd`; Vitals ignores the range entirely (ANL-043).
