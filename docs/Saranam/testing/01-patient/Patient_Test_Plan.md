## Purpose & How To Use

This document is the GO-LIVE manual test pack for the **Patient Management** module. Execute every case below in a browser against the production (or final staging) build, then record the outcome in the **Actual Result**, **Status** (Pass/Fail/Blocked), and **Remarks** columns (left blank for the tester). Work top to bottom within each section; complete the **Test Data / Preconditions** in Section 5 before starting. Log every failure as a defect using the severity legend in Section 7. The machine-readable copy of these cases lives alongside this file at `patient_test_cases.json`.

Scope at a glance: **145 test cases** across 13 functional areas, covering 6 screens and 28 API endpoints.

## 1. Scope

### In Scope
- Patient list screen: load, search, BSC/Onco/Zone filters, clear filters, grid/table view toggle, pagination, Add New Patient, row click navigation, empty & loading states
- Patient registration (PatientQuickAdd dialog): required + optional fields, +91 phone handling, approximate age, Bangalore zone auto-suggest from PIN, GPS/map location capture + zone detection, linked hospital selection + inline add, diagnosis/referral inline add, ABHA duplicate check, patient category & priority, success/UHID messaging
- Patient detail dashboard: header chips (status, UHID copy, homecare code, zone, priority), scheduling strip (edit frequency/priority/notes, flag/unflag urgent), admin UHID regeneration, tab navigation
- Overview tab: demographics, clinical status chips, body map editor (free-click markers + AI highlights), universal PPS card, care circle card, follow-up summary history, AI patient summary (generate/save/download), baseline assessment accordions, patient category & priority save, UHID preview + Mark Initial Assessment Complete (UHID assignment)
- Baseline assessment forms: Nursing, Doctor, Psychological, Physiotherapy, ESAS-R, PPS, Plan of Care (save, reload, AI summaries, validations, score bounds)
- Visits tab: list visits, create visit (follow-up/emergency/initial/teleconsult), vitals capture, teleconsult provider+time+record-call, visit detail follow-up sheet, save & mark complete, patient outcome / mark deceased from visit
- Trends tab: vitals/ESAS-R/PPS charts, source legend, vital tab selector, symptom toggles, baseline comparison, empty state
- Past Records tab: full-history timeline, type filter chips, expand/collapse events, empty state
- Patient edit screen: all demographic/clinical/location/status fields, phone +91 normalisation, Bangalore resident toggle, linked hospital + inline add, mark deceased / edit death record, save + redirect
- Mark Deceased dialog (shared): date/place/remarks validation, edit mode, care-status auto-demotion, scheduling-pool removal
- Backend API: GET/POST/PUT patients, search, duplicate-check, recent, timeline, submissions, full-history, zones detect/boundaries, UHID preview/regenerate, patient PPS, config (diagnosis-options, referral-partners, hospital-options)
- Auth/session: token attach, 401 refresh-and-retry, refresh failure redirect to /login, route guards for /patients, /patients/:id, /patients/:id/edit

### Out of Scope
- Saranam scheduling pool / day-map screens beyond the patient-detail scheduling strip
- Teleconsult session UI/video room (only the teleconsult scheduling trigger from the Visits tab is in scope)
- OPD / IPD / Encounters / Inventory dispensing modules (only their read-only appearance in the Past Records timeline is in scope)
- Authentication/login screen internals (login flow itself is a separate module; only redirect behaviour is covered)
- Generated PDF byte-level content correctness (only that the download is triggered and opens)
- AI model quality/accuracy of generated summaries and PPS suggestions (only that generate/save/persist mechanics work)
- Form Builder / dynamic form submissions creation (only the submission count + timeline display is in scope)

## 3. Roles & Access

All three routes (/patients, /patients/:id, /patients/:id/edit) require an authenticated session (valid JWT in localStorage access_token) but no special permission — any logged-in user may view, create and edit patients and assessments. The only role-gated action is UHID regeneration: the Refresh icon next to the UHID chip and the backend POST /api/patients/:id/regenerate-uhid are admin-only (require_role('admin')). A non-admin must not see the regenerate icon and the endpoint must return 403 for non-admins. Unauthenticated/expired-token access: the axios client attaches the Bearer token; on a 401 it attempts a one-time refresh via the refresh_token, and if that fails it clears localStorage and hard-redirects to /login.

## 4. API Endpoints

All endpoints are prefixed `/api/patients` and require a JWT (`Authorization: Bearer <token>`) except `/api/patients/health`.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/patients` | List/search patients. Query: q, page, per_page (max 100), sort_by, sort_order, bsc_status, is_onco, geographic_cluster. Returns {patients,total,page,per_page,total_pages}. |
| POST | `/api/patients` | Create patient. Validates PatientCreateSchema; ABHA-address duplicate check (409); returns 201 {patient}. 400 on validation error. |
| GET | `/api/patients/:id` | Get patient by UUID; records recent-access; 404 if not found. |
| PUT | `/api/patients/:id` | Update patient (all-optional PatientUpdateSchema). 200 patient, 404 if not found, 400 on validation error. |
| POST | `/api/patients/:id/regenerate-uhid` | Admin-only. Mint new UHID from current year/zone counter; old UHID kept in history. 400 if not Bangalore resident / no zone; 409 on collision; 403 non-admin. |
| GET | `/api/patients/uhid/preview` | Read-only peek at next UHID for (zone, hospital). 400 on missing/invalid zone or hospital. |
| POST | `/api/patients/:id/pps` | Record standalone patient-level PPS (visit_id=NULL); syncs latest_pps_score + clinical_complexity. 400 if pps_score not 0-100; 404 if patient missing; 201 {pps,priority}. |
| GET | `/api/patients/:id/submissions` | Paginated form submissions for a patient. 404 if patient missing. |
| GET | `/api/patients/recent` | Recently accessed patients for current user. Query limit (max 50). |
| POST | `/api/patients/search` | Advanced search with filters (gender, age range, city, state, has_abha, has_submissions, bsc_status, is_onco, geographic_cluster, date range, sort). |
| POST | `/api/patients/duplicate-check` | Check for existing patient by abha_address. Returns {duplicate_found, patient?}. |
| GET | `/api/patients/:id/timeline` | Patient timeline (creation + form submissions), newest first. 404 if patient missing. |
| GET | `/api/patients/:id/full-history` | Comprehensive cross-module history: Saranam visits+assessments, encounters, IPD admissions, dispensings, form submissions, with summary counts. Powers Past Records tab. |
| POST | `/api/patients/zones/detect` | Point-in-polygon GBA zone detection from {lat,lng}. 400 if lat/lng missing; returns {zone} or null. |
| GET | `/api/patients/zones/boundaries` | GBA zone boundary GeoJSON + colors for map overlay. |
| GET | `/api/patients/config/diagnosis-options` | List diagnosis dropdown options (DB-backed with defaults). |
| POST | `/api/patients/config/diagnosis-options` | Add a diagnosis option. 400 if blank; 409 if already exists; 201 with options. |
| PUT | `/api/patients/config/diagnosis-options` | Replace full diagnosis list. 400 if empty/non-array. |
| DELETE | `/api/patients/config/diagnosis-options` | Remove a diagnosis option. 400 blank, 404 not found. |
| GET | `/api/patients/config/referral-partners` | List referral partner options. |
| POST | `/api/patients/config/referral-partners` | Add a referral partner. 409 if exists. |
| PUT | `/api/patients/config/referral-partners` | Replace full referral partner list. |
| DELETE | `/api/patients/config/referral-partners` | Remove a referral partner. 404 not found. |
| GET | `/api/patients/config/hospital-options` | Hospital master list (active only by default; include_inactive=1 for all). |
| POST | `/api/patients/config/hospital-options` | Add hospital. Validates code (alnum 2-10), name required, prefix 5-20. 409 if code exists. |
| PUT | `/api/patients/config/hospital-options` | Replace catalog. code & homecare_prefix immutable for existing; at most one default; 422 on violation. |
| DELETE | `/api/patients/config/hospital-options` | Hard-delete if zero references else soft-delete; force=1 forces soft. 409 if deleting the default. |
| GET | `/api/patients/health` | Service health check (unauthenticated). |

## 5. Test Data / Preconditions

- At least 25 existing patients spanning >1 page (per_page is 20) with a mix of genders, ages, BSC/N-BSC, Onco/Non-Onco, all five zones (North/South/East/West/Central), some with submissions and some without.
- At least one patient in each zone with is_bangalore_resident=true + a linked hospital so UHID preview/generation can be tested.
- At least one non-Bangalore patient (is_bangalore_resident=false, no zone, no UHID) to verify UHID never assigned.
- At least one patient with an existing ABHA address (e.g. 'ramesh.kumar@abdm') to trigger the duplicate-check path.
- At least one patient already marked Deceased and one with care_status 'inactive' to verify status chips/badges.
- At least one patient with a completed initial visit + recorded ESAS-R, PPS and vitals across multiple follow-up visits so Trends and Past Records render charts/timeline.
- One admin user and one non-admin (e.g. nurse/doctor) user for permission tests on UHID regeneration.
- Valid access_token + refresh_token in localStorage; ability to corrupt/expire the access_token to test 401 handling.
- Hospital master list seeded with at least KMIO (default), KCGH and SWON.
- Diagnosis options and referral partner options seeded (defaults exist if DB empty).
- Realistic India test inputs: names (Ramesh Kumar, Lakshmi Devi, Mohammed Irfan), +91 10-digit phones (9876543210), Bangalore PINs (560004 South, 560064 North, 560001 Central), ABHA 14-digit IDs, DD/MM/YYYY DOBs.
