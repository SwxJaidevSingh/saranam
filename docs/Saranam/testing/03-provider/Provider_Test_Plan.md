# Saranam India Health Care — Providers Module Test Plan

**Module:** Providers  **Module Code:** PRV  **Version:** 1.0  **Date:** 2026-06-01

**Production URL:** https://saranam.fieldintel.ai

## Purpose & How To Use

This is the GO-LIVE manual test pack for the **Providers (Healthcare Providers)** module of the Saranam India Health Care platform (React frontend + FastAPI/Flask backend). The testing team executes each case manually in a browser and records the outcome in the **Actual Result**, **Status** (Pass/Fail/Blocked), and **Remarks** columns (kept blank here and in the companion Excel).

How to use:

1. Complete the **Test Data / Preconditions** (Section 5) before starting a run.
2. Execute cases top to bottom within each section; numbered steps in each row are sequential.
3. Compare observed behaviour against **Expected Result** and mark Status. Capture screenshots and console/network details for any Fail.
4. Several cases call out **known behaviours / suspected defects** (parameter mismatch, "All" status filter, missing pagination, no client-side time/phone validation). If observed, log them with severity for the dev team.
5. The machine-readable source of truth for these cases is `provider_test_cases.json` in this same folder — keep the two in sync.

## 1. Scope

**In scope**

- Providers list page (/providers): initial load, search by name/license/HPR ID, specialization filter, status filter (All/Active/Inactive), refresh button, provider card grid, count display, card click and View Details navigation, loading state, empty state, error alert
- Create provider (/providers/new) via ProviderForm: all fields, required-field validation (full_name, specialization), email/phone/postal/duration format, signature image upload (PNG/JPG, max 500KB client), save success/failure, cancel/back
- Edit provider (/providers/:id/edit): prefilled form, update, status (Active/Inactive) change
- AddOptionDialog: inline add new specialization, min-length validation, duplicate/error handling, auto-select after add
- Manage Specializations dialog: list specializations, soft-delete a specialization, empty list message
- Provider detail (/providers/:id): status/teleconsult badges, basic info, contact info, bio, stats, Appointments tab, Schedule preview tab, Manage Schedule navigation, Edit, Deactivate with browser confirm
- Provider Schedule Manager (/providers/:id/schedule): load/default schedule, toggle days, start/end time, slot duration, capacity per slot, Apply to All Active Days, bulk save, success/error feedback
- REST API endpoints for providers, specializations, departments, schedule, availability, appointments, signature upload, quick-create, unknown-provider
- Auth/session: protected routes require login; 401 triggers token refresh then redirect to /login on failure
- Data integrity: new provider appears in providers list and is selectable in scheduling/visit-assignment selectors; new specialization appears in filter and form dropdowns

**Out of scope**

- Appointment creation/edit business logic (covered by Scheduling module PRV defers to that pack); only the embedded AppointmentList/AppointmentDetailsModal rendering within provider detail is sanity-checked
- Department filter and Add Department dialog (commented out in current UI, endpoints exist but are not wired to any screen)
- Bulk import flow and quick-create / unknown-provider UI (no provider-module screen invokes them; API-only coverage included)
- Prescription PDF rendering of the uploaded signature (covered by prescription/visit module)
- Login screen itself, role/permission management UI (Users module)
- Cross-browser/device matrix beyond a single primary desktop browser unless explicitly noted
- Performance/load and security penetration testing

## 3. Roles & Access

All provider routes (/providers, /providers/new, /providers/:id, /providers/:id/edit, /providers/:id/schedule) are wrapped in the authenticated layout in App.jsx and require a valid login (JWT access_token in localStorage). There is no provider-specific role/permission gate beyond authentication, so any logged-in user may view, create, edit, deactivate providers and manage schedules. Every backend endpoint is decorated with @jwt_required(), so an unauthenticated or expired-token request returns 401. The axios response interceptor in api/client.js intercepts a 401, attempts a one-time token refresh using the refresh_token; if refresh succeeds the original request is retried, if it fails (or no refresh_token) all tokens/user are cleared from localStorage and the browser is hard-redirected to /login.

## 4. API Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/providers` | List/search providers. Query params from UI: limit (hardcoded 100), search, specialization, is_active. Backend reads q, specialization, department, is_active(default true), page, per_page(max 100), sort_by(full_name), sort_order(asc). Returns {providers,total,page,per_page,total_pages}. 200 success, 500 on error. |
| GET | `/api/providers/specializations` | Get all specializations. Returns {specializations:[...]}. 200; 500 on error. |
| POST | `/api/providers/specializations` | Add a custom specialization. Body {name}. 201 created; 400 if name missing or invalid (ValueError, e.g. duplicate); 500 on error. |
| DELETE | `/api/providers/specializations/{name}` | Soft-delete (deactivate) a specialization by name (URL-encoded, path converter). 200 message; 404 if not found; 500 on error. |
| GET | `/api/providers/departments` | Get all departments. Returns {departments:[...]}. 200; 500 on error. (UI not wired.) |
| POST | `/api/providers/departments` | Add a custom department. Body {name}. 201; 400 if missing; 500. (UI not wired.) |
| GET | `/api/providers/{provider_id}` | Get one provider by UUID. 200 with provider object; 404 if not found; 500 on error. Non-UUID path segment is not matched by <uuid:...> route and yields 404 (Flask routing). |
| POST | `/api/providers` | Create a provider. Body = full form data. 201 created; 400 on ValueError (validation); 500 on error. |
| PUT | `/api/providers/{provider_id}` | Update a provider. Body = form data. 200 updated; 404 if not found; 400 on ValueError; 500 on error. |
| DELETE | `/api/providers/{provider_id}` | Soft-delete / deactivate a provider. 200 {message}; 404 if not found; 500 on error. |
| POST | `/api/providers/{provider_id}/signature` | Upload signature image (multipart, field 'signature'). Accepts image/png\|jpeg\|jpg\|webp. 200 {signature_image,storage}; 404 if provider missing; 400 if no file / wrong mime / empty / >5MB; Cloudinary or base64 storage. |
| GET | `/api/providers/{provider_id}/appointments` | Get provider appointments. Params from_date,to_date,status,page,per_page. Returns {appointments,total,page,per_page,total_pages}. 200; 500 on error. |
| GET | `/api/providers/{provider_id}/schedule` | Get weekly schedule. Returns {schedules:[{day_of_week,day_name,start_time,end_time,slot_duration,...}]}. 200. |
| POST | `/api/providers/{provider_id}/schedule` | Create/update single schedule entry. Body = schedule object. (Helper createSchedule; not used by Schedule Manager which uses bulk.) |
| POST | `/api/providers/{provider_id}/schedule/bulk` | Bulk create/replace weekly schedules. Body {schedules:[7 day objects]}. Used by Schedule Manager Save. Success returns created schedules; error returns {error}. |
| PUT | `/api/providers/{provider_id}/schedule/{dayOfWeek}` | Update schedule for a specific day (0-6). (Helper updateDaySchedule; not directly wired to a button.) |
| DELETE | `/api/providers/{provider_id}/schedule/{dayOfWeek}` | Delete schedule for a specific day (0-6). (Helper deleteDaySchedule.) |
| GET | `/api/providers/{provider_id}/availability` | Available slots for a date. Params date(required),duration(optional). (Helper getAvailability; consumed by scheduling.) |
| GET | `/api/providers/{provider_id}/availability/range` | Available slots for a date range. Params from_date,to_date,duration. (Helper getAvailabilityRange.) |
| POST | `/api/providers/quick-create` | Quick create provider for bulk import. Body {full_name(required),specialization,phone,email,bulk_import_session_id}. 201; 400 if full_name missing. (API-only.) |
| GET | `/api/providers/unknown-provider` | Get or create 'Unknown Provider' placeholder for bulk imports. 200. (API-only.) |

## 5. Test Data / Preconditions

- A valid login account with access to the platform (any authenticated user works; no special role required). Have valid email + password ready.
- At least 5 existing active providers with varied specializations (e.g., Dr. Anjali Rao - Palliative Medicine, Dr. Vikram Nair - Oncology, Nurse Lakshmi Iyer - Home Care Nursing) and at least 1 inactive provider for status-filter checks.
- At least one provider WITH a defined weekly schedule and one provider WITHOUT any schedule (to test empty schedule preview + Setup Schedule).
- At least one provider WITH stats/appointments and one freshly created provider with zero appointments.
- A second browser/incognito profile or a way to clear localStorage tokens to exercise 401/session redirect.
- Sample signature images: a valid PNG ~50KB, a valid JPG ~200KB, an oversized PNG > 500KB, and a non-image file (e.g., a .pdf or .txt renamed) for negative upload tests.
- A note of one valid existing provider UUID (copy from a detail URL) and one syntactically-valid-but-nonexistent UUID (e.g., 00000000-0000-0000-0000-000000000000) plus one clearly malformed id (e.g., 'abc123').
- Realistic India test data: phone +91-9876543210, email test.doctor@saranam.in, postal code 560001, city Bangalore, state Karnataka, license FM-2026-001, HPR ID HPR-123456, qualification MBBS, MD.
